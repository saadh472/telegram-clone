# Full-Stack Deployment Guide

This project is deployable as one full-stack web service:

- Flask serves the REST API at `/api`.
- Flask serves the vanilla frontend from the same domain.
- SQLite is initialized automatically on first boot.
- No SQL Server, ODBC driver, or manual database setup is required for the deployed demo.

## Recommended CV Deployment

Use Render with the included `render.yaml` blueprint.

Render will build `backend/Dockerfile`, run `start_production.py`, create/seed the SQLite database, and serve the app with Gunicorn.

The final app URL will look like:

```text
https://telegram-clone-fullstack.onrender.com
```

The exact subdomain can differ if Render asks for a unique service name.

## Deploy From GitHub

1. Push the latest code to GitHub.
2. Open Render Dashboard.
3. Choose **New +**.
4. Choose **Blueprint**.
5. Connect `saadh472/telegram-clone`.
6. Select the root `render.yaml`.
7. Click **Apply**.
8. Wait for the first deploy to finish.
9. Open the service URL.

Health check:

```text
https://YOUR-RENDER-SERVICE.onrender.com/api/health
```

Expected response:

```json
{
  "database": "connected",
  "engine": "sqlite",
  "status": "ok"
}
```

Demo login:

```text
username: saad
password: 12345678
```

## Production Environment

The Render blueprint sets these variables:

| Variable | Value |
| --- | --- |
| `FLASK_HOST` | `0.0.0.0` |
| `FLASK_DEBUG` | `false` |
| `SERVE_FRONTEND` | `true` |
| `FRONTEND_DIR` | `/app/frontend` |
| `DB_ENGINE` | `sqlite` |
| `SQLITE_DB_PATH` | `/app/data/telegram_clone.db` |
| `JWT_SECRET` | generated by Render |

The Docker startup requires a custom `JWT_SECRET`. The Render Blueprint generates it automatically.

## Data Persistence

This setup is for a portfolio demo. The seeded account uses public demo credentials, and seed-version changes can reset its conversations. On hosts with ephemeral storage, messages can also reset after a restart or redeploy.

For persistent demo data, mount a persistent disk at `/app/data`.

## Local SQLite Smoke Test

Start the app with the [SQLite quick start](../README.md#quick-start). In a second terminal from the repository root, run:

    python backend/tests/smoke_api.py

## Optional GitHub Pages frontend

GitHub Pages can serve the frontend while Flask runs on a separate host. Configure the repository's Pages source to **GitHub Actions**, set the repository variable `API_BASE_URL` to the HTTPS API URL ending in `/api`, and add the Pages site's origin to the backend's `CORS_ORIGINS`. In the **Actions** tab, run **Deploy Frontend to GitHub Pages** manually.

## Local SQL Server Still Works

For the original SSMS workflow, keep:

```text
DB_ENGINE=sqlserver
SQL_SERVER=localhost\SQLEXPRESS
DB_NAME=TelegramClone
```

Then run:

```powershell
python backend\app.py
```
